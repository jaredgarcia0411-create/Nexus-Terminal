## Summary

The suite is healthy overall. Core parser, indicator, time, schema-isolation, and primary trade route behavior are covered well, naming is generally descriptive, async handling is clean, and the suite is fast. Based on the current shape, this is a good baseline test suite for a small app, but coverage breadth is still uneven across major product surfaces.

The main risk is missing coverage, not obviously broken tests. Large parts of the active app remain untested: several API routes, nearly all hooks, and most major UI workflows. The most important concrete issue inside the current tests is one suite missing `vi.clearAllMocks()` in `beforeEach`, which increases cross-test pollution risk.

## Anti-Patterns Found

### Critical (1)

1. **Missing mock reset**: `__tests__/askedgar-client.test.ts:66-73`
   - `beforeEach()` restores spies and resets modules, but it does not call `vi.clearAllMocks()`.
   - **Fix**: add `vi.clearAllMocks()` at the top of `beforeEach()` so any hoisted/mock call state cannot leak across tests.

### Warnings (9)

1. **Implementation-detail assertions**: `__tests__/server-db-utils.test.ts:96-128`
   - Tests assert `_mocks.updateSet`, `_mocks.insertValues`, and `_mocks.conflictUpdate` internals instead of primarily checking observable `ensureUser()` behavior.
   - **Fix**: keep one light internal wiring assertion if needed, but bias toward returned data and externally visible DB effects.

2. **Implementation-detail assertions**: `__tests__/market-data-route.test.ts:84-90`, `:126-127`
   - Tests inspect `globalThis.fetch.mock.calls[0][0]` and parse the exact upstream URL. This is brittle to harmless refactors.
   - **Fix**: assert the response contract first, then only keep targeted upstream request assertions when behavior truly depends on them.

3. **Thin UI smoke test**: `__tests__/research-tab.test.tsx:8-15`
   - Uses `renderToStaticMarkup()` and string matching instead of DOM-based behavior checks.
   - **Fix**: render with Testing Library and assert visible states/interactions.

4. **Thin UI smoke test**: `__tests__/charts-tab.test.ts:8-36`
   - Same static markup pattern; good as a smoke test, weak as workflow coverage.
   - **Fix**: add focused interaction/state tests around controls and derived UI.

5. **Duplicate route setup**: `__tests__/saved-tickers-route.test.ts`, `__tests__/market-data-daily-summary-route.test.ts`
   - Repeated hoisted auth/db mock setup is very similar to other route suites.
   - **Fix**: extract shared helpers where repetition is getting in the way of readability.

6. **Internal helper coupling**: `__tests__/trade-id-route.test.ts:140-156`, `:245-249`
   - Assertions focus heavily on helper call shape and update wiring.
   - **Fix**: prioritize route input/output and persisted outcome checks.

7. **Noisy expected-error tests**: `__tests__/market-data-route.test.ts`, `__tests__/trades-import-route.test.ts`
   - Successful tests still print expected `stderr`, which makes failures harder to scan.
   - **Fix**: stub or silence expected error logging in those cases.
